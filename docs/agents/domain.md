# Domain docs

## 탐색 전에 읽기

1. 제품 요구사항 원본은 `docs/caregiving_notebook_requirements.md`다. 작업 계획·코드 변경 전에 전체를 읽는다.
2. 루트에 `GLOSSARY.md`가 있으면 도메인 용어와 정의를 읽는다.
3. `docs/adr/`가 있으면 작업 영역과 관련된 설계 결정 기록을 읽는다.

용어집이나 ADR이 아직 없으면 기존 요구사항과 코드를 바탕으로 진행한다. 빈 문서를 미리 만들지 않는다. 용어나 설계 결정을 실제로 정리할 때 해당 문서를 만든다.

## 문서 배치

이 저장소는 Flutter 앱과 Python 개발·데이터 도구가 같은 제품을 지원하는 단일 문맥으로 관리한다.

- `GLOSSARY.md`: 제품 도메인 용어와 정의
- `docs/adr/`: 번호를 붙인 설계 결정 기록

코드·이슈·설계 제안·시험에서 같은 개념에는 용어집의 표현을 사용한다. 필요한 정의가 없으면 기존 프로젝트 용어를 먼저 확인하고, 실제 정의가 필요한 경우 domain-modeling 작업에서 보완한다.

기존 ADR과 충돌하는 제안은 해당 ADR과 충돌 이유를 명시한다. 제품 범위·의료 안전·개인정보 원칙은 루트 `AGENTS.md`와 제품 요구사항을 따른다.
