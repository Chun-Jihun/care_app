# AI 없이 사용하는 간병수첩 — 구현 전 실패 시나리오

기준: `caregiving_notebook_requirements.md` 전체. 사용자 요청에 따라 Android와 iOS를 위한 Flutter 기반의 로컬 기록 앱을 만든다. 이번 단계는 직접 입력·확인한 기록을 관리하는 기능이며, 의료 지식·상호작용 판정·위험 규칙·OCR·음성 전사는 승인·모델 연결 단계로 남긴다.

## 제품 범위

- 회원가입 없는 환자 본인·가족·동거인용 로컬 프로필과 환자 전환. 이름은 선택.
- 오늘 화면, 빠른/상세 기록, 날짜·종류·검색어 필터, 수정 이력과 삭제.
- 식사·수분, 실제 복약, 증상·측정값, 활동, 수면·배설·위생·피부, 사건·진료 연락·인계·자유 메모.
- 직접 입력한 약 목록과 처방 지시, 버전을 보존하는 복약 일정, 복용함/누락/거부/모름 기록.
- 일정·할 일·진료 질문, 의료진 설명 원문, 원본 기록을 선택하는 진료 준비, 간병인 점검.
- 사진과 처방자료 첨부·열람·삭제, 로컬 알림, OS 인증을 통한 앱 잠금.
- 암호화 SQLite와 첨부파일, OS 보안 키 저장소, 비밀번호로 보호한 선택적 로컬 백업·복원과 전체 삭제.
- AI가 연결되지 않아도 모든 위 기능이 실행된다. 새 의료 판단, 가족 계정 공유, 서버·클라우드 동기화는 제공하지 않는다.

## 구현 전에 고정한 시험

| ID | 실패 | 방어·검증 |
|---|---|---|
| LOCAL-01 | 재시작 후 기록 소실 | 실제 SQLCipher 파일을 닫고 다시 열어 기록·약·일정·사진 메타데이터를 검증 |
| LOCAL-02 | 잘못된 키 또는 평문 SQLite로 열림 | cipher_version 확인 실패 시 중단, 잘못된 키 거부, 디스크에서 합성 원문 미검출 |
| LOCAL-03 | 다른 환자 조회·수정·연결 | 모든 CRUD에 환자 범위, 복합 FK, 교차 환자 ID 변조 시험 |
| LOCAL-04 | 수정 충돌·수정 전 값 소실 | 낙관적 version 검사와 동일 트랜잭션의 수정 이력 저장 |
| LOCAL-05 | 수정으로 과거 처방 변조 | 새 일정 버전 생성, 실제 복약은 당시 지시를 보존 |
| LOCAL-06 | 알림을 복용 완료로 오해 | 알림/할 일 상태와 실제 복약 분리, 누락·모름을 자동 복용으로 변경하지 않음 |
| LOCAL-07 | 기록 삭제 뒤 이력·첨부·진료 메모에 원문 잔존 | DB 관계 삭제, 파일 키 삭제, 원본 연결 제거·재검토 표시, 삭제 작업 재시작 복구 |
| LOCAL-08 | 복원 실패로 기존 기록 파손 | 암호·인증태그·형식·버전·무결성 검증 후 교체, 실패 시 기존 데이터 유지 |
| LOCAL-09 | 사진·파일명·EXIF·썸네일 평문 저장 | 메모리에서 메타데이터 제거, 불투명 ID와 파일별 암호화, 외부 썸네일 캐시 미사용 |
| LOCAL-10 | 화면 전환·백그라운드에서 기록 노출 | 잠금 시 민감 UI 가림, 재인증, Android 스크린 보호/iOS 앱 전환 가림 구성 |
| LOCAL-11 | 로그·네트워크·OS 백업에 기록 노출 | 네트워크 권한/분석 SDK 없음, 원문 오류로그 없음, Android 자동 백업 금지/iOS 로컬 저장 백업 제외 |
| LOCAL-12 | 측정값 단위·시각 누락 | 항목별 입력 검증, UTC와 입력 시차 보존, 임상 임계값을 임의 생성하지 않음 |
| LOCAL-13 | 사용자 입력을 임상 검수 지시로 승격 | 의료진 설명은 사용자가 옮긴 원문으로 표시, clinician_verified 자동 설정 없음 |
| LOCAL-14 | 앱 오류가 기록 성공처럼 표시 | 저장 완료 후 UI 갱신, 실패 시 입력 유지·일반 오류 표시, 중복 저장 방지 |

자동 검증은 Flutter 단위·위젯 시험과 실제 SQLCipher 통합 시험으로 나눈다. 네이티브 인증·알림·파일 선택은 플랫폼 어댑터로 분리하고 실제 기기에서 추가 검증해야 한다. Windows 환경에서 iOS 실기기 검증을 완료했다고 표현하지 않는다.

## 구현 선택

Flutter 공통 화면·도메인·저장 로직을 사용한다. AI 없이 사용하는 경로가 향후 AI 런타임에 의존하지 않도록 `domain / application / infrastructure / presentation` 경계를 둔다. 데이터베이스 암호화는 SQLCipher 활성 여부를 실행 중 확인하며 평문으로 대체하지 않는다.

사용자가 명시적으로 선택하는 파일 내보내기는 암호화 백업으로 제공한다. 파일 선택기가 제공하는 저장 목적지는 사용자가 결정하며 앱은 자동 업로드하지 않는다. 진료 준비와 인계 기록은 앱 내부에서 열람한다.

의료 규칙도 AI가 아닌 코드로 만들 수 있지만 승인 자료와 임상 검수 없이 활성화하지 않는다. 이 제한은 요구사항 8.4에 따른다. 기본 앱에서는 사용자가 저장한 연락처와 119 전화 화면 열기를 제공한다.
