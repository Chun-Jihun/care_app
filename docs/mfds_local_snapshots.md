# 의약품 허가정보·DUR 로컬 수집

## 구현 전 정의한 실패 검사

- 공식 HTTPS 호스트·서비스 경로 이외에는 키를 보내지 않는다. 리디렉션과 키가 반사된 응답도 저장하지 않는다.
- 오류, 빈 중간 페이지, 총 건수 변화, 반복 페이지, 원문 해시 불일치는 완료 처리를 차단한다.
- 중단된 수집은 저장된 페이지를 검증한 뒤 재개한다. 이전 완료 스냅샷은 수정하지 않는다.
- 로컬 DB는 전체 페이지를 검증한 이후에 생성하며, 조회는 API·환경변수 없이 가능해야 한다.
- 병용금기 상대 품목도 조회한다. 조회 결과 없음은 안전함을 뜻하지 않는다.
- 수집 완료와 임상 검수는 구분한다. 모든 신규 자료는 미검수이며 앱 근거·학습 데이터로 자동 승인하지 않는다.
- 다운로드 원문, DB, 키, PDF와 저장 웹페이지는 Git에서 제외하고 재현용 코드·출처 메타데이터만 관리한다.

## 출처와 범위

- [의약품 제품 허가정보](https://www.data.go.kr/data/15095677/openapi.do): 허가 목록, 상세 허가정보, 주성분 상세정보 3개 API.
- [DUR 품목정보](https://www.data.go.kr/data/15059486/openapi.do): 품목정보와 병용금기·특정연령금기·임부금기·용량주의·투여기간주의·노인주의·효능군중복주의·서방정분할주의 9개 API.

공개 API는 수집 시점에만 PC에서 호출한다. 이 작업은 모바일 앱의 의료 답변 또는 개인별 상호작용 판단 기능을 활성화하지 않는다. API 원문의 XML/HTML 형식인 설명 필드도 실행하거나 재해석하지 않고 보존한다.

## 실행

Python 3.11 이상 표준 라이브러리만 사용한다. `.env.example`의 세 서비스 키는 서로 독립적이다. 기존 `.env`는 덮어쓰지 않는다.

```powershell
python scripts/fetch_mfds_local.py fetch --dry-run
python scripts/fetch_mfds_local.py fetch --service all --snapshot-id 20260918T053000Z
# 중단 시 동일 ID/페이지 크기로 재개한다. 완료된 서비스의 원문은 다시 받지 않는다.
python scripts/fetch_mfds_local.py fetch --service all --snapshot-id 20260918T053000Z --resume
# 원문에서 DB만 다시 생성하는 작업은 네트워크를 사용하지 않는다.
python scripts/fetch_mfds_local.py index --snapshot data/mfds/permits/20260918T053000Z
# 품목코드 또는 제품명으로 원문을 확인한다. 다음 코드는 형식 예시다.
python scripts/fetch_mfds_local.py query --snapshot data/mfds/dur/20260918T053000Z --item-seq 000000000
```

`--service permits`는 허가정보, `--service dur`은 DUR만 수집한다. 새로운 날짜의 갱신은 새 `--snapshot-id`로 실행한다. 이전 스냅샷은 덮어쓰지 않는다. 완성된 데이터의 위치는 `data/mfds/<service>/<snapshot-id>/`이며 다음을 포함한다.

- `raw/<operation>/page-*.json`: API 응답 원문.
- `manifest.json`: 작업별 전체 건수, 페이지 순서·해시·수집 시각, 완료 여부, 검수 상태.
- `catalog.sqlite3`: 품목코드·병용 상대 품목코드 인덱스와 원문 레코드.
- `index.json`: DB 해시와 생성에 사용한 원문 manifest 해시.

페이지 크기 기본값은 500건으로, 확인한 API 상한에 맞췄다. `--num-rows`를 변경해 수집했다면 재개 시에도 같은 값을 지정한다. 한 실행에서 서비스별 기본 최대 9,500페이지를 요청한다. 통신 재시도는 별도 요청으로 계산된다. 일일 할당량을 초과하면 미완료 상태로 멈추므로 할당량이 갱신된 이후 재개한다. OS 강제 종료로 `.스냅샷ID.collect.lock`이 남은 경우, 해당 수집 프로세스가 종료됐는지 확인한 후 그 잠금 파일만 제거한다.

검증 실패 또는 중간 빈 페이지를 마지막 페이지로 오인하지 않는다. 성공한 마지막 페이지까지 체크포인트를 남기고, 재개 시 이미 받은 페이지 해시·개수·순서를 검증한다. 파일 변경을 감지하면 원문을 덮어쓰지 않고 중단한다. DB는 원문 전체 검증 후 별도 임시 파일에서 생성한다.

## 해석상의 한계

API는 원자적인 전체 덤프를 제공하지 않는 실시간 페이지 조회다. 총 건수 변화·반복 페이지·파일 손상은 검출하지만, 수집 도중 총 건수가 같은 수정·교체까지 완벽하게 배제할 수는 없다. `consistency` 필드에 이 한계를 기록한다. 원문 `CHANGE_DATE`·허가취소 정보와 수집 시각을 보존하며, 수집일을 발행일이나 임상 검수일로 대체하지 않는다.

API 작업마다 포함하는 품목 범위가 다를 수 있다. 실제 수집에서 주성분 상세의 고유 품목코드는 74,144개로 허가 목록의 42,992개와 달랐다. 조인되지 않는 원문도 그대로 보존한다. 주성분 정보가 있다는 이유만으로 현재 허가 유효성이나 국내 유통 여부를 판정하지 않는다.

의료진 검수, 개별 원문 인용 연결, 갱신 주기와 유효기간 승인, 모바일 배포용 데이터 최소화는 이후 별도 작업이다. 로컬 조회 DB는 개발·검수용이며 환자의 약 조합을 판정하는 엔진이 아니다. 검색 결과가 없거나 `has_more=true`이면 전체 관계를 확인했다는 뜻이 아니다.

## 2026-09-18 수집·검증 결과

완료 스냅샷 ID는 두 서비스 모두 `20260918T053000Z`다.

| 서비스 | 수집 범위 | 원문 페이지 | 저장 레코드 |
|---|---|---:|---:|
| 허가정보 | 품목 목록 42,992건 + 상세 42,992건 + 주성분 126,871행 | 426 | 212,855 |
| DUR | 품목 및 금기·주의 9종, 병용금기 796,710행 포함 | 1,720 | 857,362 |

레코드 합계는 고유 제품 수가 아니다. 원문과 조회 DB를 합쳐 허가정보는 약 4.6 GiB, DUR은 약 2.9 GiB를 사용한다. 앞서 100건 페이지로 시험 수집한 `20260918T052000Z`는 미완료 상태로 별도 보존했으며 완료 DB가 없다.

모든 원문 페이지의 SHA-256·페이지 순서·건수 검사와 두 DB의 SQLite `integrity_check`가 통과했다. 네트워크를 차단한 조회에서 허가·상세·주성분 연결 및 실제 병용금기 한 쌍의 양방향 품목코드 조회를 확인했다. 수집·재개·손상 감지·오프라인 조회·기존 e약은요 처리 관련 단위 테스트 45개가 통과했다. 이 결과는 기술 검증이며 의료 검수가 아니다.
