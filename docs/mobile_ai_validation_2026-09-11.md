# Android AI 실행 검증 — 2026-09-11

학습한 세 모델을 Flutter 앱의 로컬 런타임에서 실제 실행했다. Android 실행 연결은 확인했으며
모델 품질·의료 출시 게이트는 **통과 처리하지 않는다**. iOS AI와 실제 휴대전화 AI 시험은 남아 있다.

## 환경과 범위

- Windows, Flutter 3.47.2 / Dart 3.13.2, JDK 21.
- AI 전용 Android 15 x86_64 AVD `care_ai_validation`, 4 GB RAM, CPU 2개, 소프트웨어 그래픽.
- llama.cpp는 앱과 같은 고정 revision의 x86_64 빌드. 에뮬레이터가 지원하는 AVX2/FMA 등 사용.
  실제 휴대전화용 arm64 APK는 공식 AAR을 사용한다. 이 시험을 arm64 실기기 성능으로 해석하지 않는다.
- `.careai` v2를 앱 전용 폴더에 설치하고 manifest/모델 해시 검증 후 추론했다.
- 합성 OCR 20건, 언어별 합성 조회 5건, 공개 음성 4건, 무음 1건, 네이티브 취소·재사용 1건.
  환자 기록이나 사용자의 마이크 음성을 시험 자료로 사용하지 않았다.

## 결과

| 항목 | 실제 실행 | 정확도/동작 |
|---|---|---|
| 챗봇 필터 | 5/5 결과 반환, 네이티브 오류 0 | 기대 필터 3/5 일치. 영어·일본어에서 항목 누락, 앱은 추가 확인 안내 |
| OCR | 20/20 결과 반환, 네이티브 오류 0 | 공백·대소문자 정규화 후 19/20 완전 일치, CER 약 0.99% |
| 음성 전사 | 4/4 결과 반환, 네이티브 오류 0 | 같은 정규화 후 1/4 완전 일치, CER 약 10.79% |
| 무음 | 3초 PCM 입력 | 전사하지 않고 `noSpeech` 반환 |
| 동시 실행·취소 | 진행 중 새 요청 차단 | 취소 결과 2ms 반환, 이전 native 자원 정리 후 OCR 재실행 성공 |

OCR/음성의 원시 보고서 `passed`는 `pass_criterion=nonempty_native_output`일 때 **결과 반환 여부**다.
정확도와 혼동하지 않도록 원문·기준문·CER를 별도로 보관했다. CER는 Unicode casefold와 공백 제거만
적용한 문자 편집 거리다. 이전 PC 평가와 표본·실행 형식이 다르므로 수치를 직접 비교하지 않는다.
이 작은 표본은 학습 검증·임상 정확도 평가를 대체하지 않는다.

응답 시간은 모델 파일 확인을 포함한 첫 챗봇 약 32.9초, 이후 약 11.1~13.6초,
OCR 약 0.40~0.79초, 음성 약 4.61~7.39초였다. 다른 개발 작업을 병행한 에뮬레이터 값이다.
네이티브 취소 후 내부 연산이 반환할 때까지 새 요청을 차단하는 동작도 확인했다.

## 남아 있는 품질 오류

- 영어 `Show the blood pressure recorded at 09:30 on 2026-09-11.`는 item을 null로 반환했다.
- 일본어 대응 질문은 kind를 medical, item을 null로 반환했다. 앱은 모델 원문을 표시하지 않고
  조회 조건을 재확인한다. UI의 언어 지원이 모델 정확도 보장을 뜻하지 않는다.
- 한글의 여백이 작은 단일 행 `V12016 복용하지 않음`에서 검출이 분리되고 단어 일부가 누락됐다.
  같은 문장이 포함된 전체 페이지는 맞게 읽었지만, 이것이 단일 행 오류를 상쇄하지 않는다.
- 한국어 공개 음성의 `시위대는`이 `12대는`으로, 일본어·중국어에서도 일부 단어가 틀렸다.
  숫자처럼 보이는 잘못된 전사가 생길 수 있으므로 결과를 자동 확정·복약 처리하지 않는다.

학습을 추가로 하거나 모델/양자화/프롬프트를 바꾸면 별도 보류한 자료로 다시 평가해야 한다.
이번 연결 작업의 실패 사례를 학습한 뒤 같은 표본의 성적만으로 개선을 주장하면 안 된다.

## 코드·저장·배포 검증

- Flutter 정적 분석: 오류·경고 없음.
- Flutter 테스트: 78개 통과. 기존 기록·잠금·초안·암호화 백업 회귀 포함.
- AI 전용 시험: 의료 요청 선행 보류, 날짜·시각·JSON 검증, 별칭 마스킹, 선택 수첩 범위,
  늦은 답변 폐기, 질문 삭제/보관 정책, OCR·음성 자동 저장 금지, OCR 편집·취소·명시적 반영.
- 백업: 답변 출처의 새 ID 연결, 출처를 제외한 선택 백업, 문서 v1 및 기존 schema 3 백업 호환.
- 모델 설치: 변조·중단·불완전 설치 차단, 손상 후 재설치, 버려진 설치 폴더 정리.
- Python 회귀시험: 135개 통과.
- 번역 생성기: 573개 메시지 / 한국어·영어·일본어·간체·번체 검증.
- Android arm64 release APK 빌드 성공(62,125,564 bytes, Flutter 표시 약 59.2 MiB).
  개발 서명이며 스토어 배포본은 아니다.
- APK 권한 검사: RECORD_AUDIO 포함, INTERNET 권한 없음. arm64 라이브러리의 ELF LOAD 16 KB
  정렬을 검사했다. 실제 16 KB 페이지 기기에서의 실행 시험을 대신하지 않는다.
  `zipalign -c -P 16 4` 검사도 통과했다.

중간 실행에서 찾은 설치 전송 오류, MTP 메타데이터 오류, ONNX 중복 라이브러리,
실행 공간에 전달할 수 없는 객체 포획, 한 줄 OCR 분리, APK의 불필요한 다른 ABI 포함을 수정했다.
