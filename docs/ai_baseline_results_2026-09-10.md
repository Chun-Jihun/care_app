# 챗봇·OCR·음성 전사 기준선 실험 — 2026-09-10

첫 PC 비교 실험과 구조·표기 처리 대조시험을 완료했다. 현재 우선안은 **챗봇의 조건 추출과 호스트 조회, PP-OCRv5 언어별 조합, Whisper small을 중심으로 한 모바일 전사 검증**이다. 추가 학습·증류를 시작하기 전에 입력 처리와 역할 분담에서 해결되는 오류가 많았다.

검증된 상세 집계는 [실행 결과 표](../experiments/ai_baseline_v1/results/completed-2026-09-10/results.md)와 [언어별 결과 JSON](../experiments/ai_baseline_v1/results/completed-2026-09-10/results.json)에 보관했다. 환경 오류·수정 전 이력·일부 사례 재실행은 채택 비교와 구분했다.

## 실험 범위

[모델 조사](ai_model_research_2026-09-10.md)의 후속 실행이다. 앱 코드·기존 고정 실험·의료 지식베이스 승인 상태는 변경하지 않았다. 새 모델은 PC 실험에만 사용한다. 이 기준선 실험에서는 추가 학습·증류·모바일 변환을 수행하지 않았다. 이후 사용자가 요청한 학습은 [별도 파일럿 결과](ai_training_results_2026-09-11.md)에 기록한다.

- 챗봇: Qwen3.5-2B/4B, Gemma 4 E2B의 제한된 기록 조회·원문 복사·보류. 기본 조건과 JSON 문법 강제, 질문의 조건만 추출하고 호스트가 조회하는 방식을 구분한다.
- OCR: PP-OCRv5 mobile detection + 한국어 recognition 또는 다국어 recognition. 합성 문서 200장 중 각 모델이 지원하는 언어만 검사한다.
- ASR: Whisper base/small 다국어판, Qwen3-ASR-0.6B. FLEURS validation 4개 언어 각 50건과 1/3/10초 무음 대조군이다.

평가 입력은 실제 환자 자료가 아닌 합성 기록·문서와 공개 읽기 음성이다. 모든 결과는 `evaluation_eligible=false`, `medical_release_gate_result=false`다. 모델 크기·성능 수치를 의료 정확도로 해석하지 않는다.

## 챗봇: 공통 40건과 확장 검사

다섯 언어 각 8건, 같은 질문과 기록으로 비교했다. `정확`은 최종 상태·선택 ID·원문 값이 모두 기대 결과와 일치한 건수다. 영어 한 개의 시스템 프롬프트를 사용한 개발용 계약 시험이며 일반적인 언어 능력 순위가 아니다.

| 방식 | 모델 | 정확 | JSON 형식 | 평균 건별 시간 | peak GPU 할당 |
|---|---|---:|---:|---:|---:|
| 기본: 기록을 읽고 값까지 출력 | Qwen3.5-2B | 7/40 | 35/40 | 3.77초 | 1.94 GiB |
| 기본: 기록을 읽고 값까지 출력 | Qwen3.5-4B | 22/40 | 40/40 | 2.57초 | 3.45 GiB |
| 기본: 기록을 읽고 값까지 출력 | Gemma 4 E2B | 1/40 | 1/40 | 6.96초 | 6.48 GiB |
| JSON 문법 강제, 종료 토큰 수정 후 | Qwen3.5-2B | 10/40 | 40/40 | 4.65초 | 1.94 GiB |
| JSON 문법 강제, 종료 토큰 수정 후 | Gemma 4 E2B | 1/40 | 40/40 | 5.66초 | 6.48 GiB |
| 조건 추출 + 프로그램이 조회·원문 표시 | Qwen3.5-2B | 39/40 | 40/40 | 2.70초 | 전체 200건에서 1.95 GiB |
| 조건 추출 + 프로그램이 조회·원문 표시 | Qwen3.5-4B | 40/40 | 40/40 | 3.88초 | 3.48 GiB |

Gemma 기본 출력 39건이 코드 블록으로 감싸져 있었다. 코드 블록만 제거하면 JSON은 38/40이지만 내용까지 맞은 것은 1/40이었다. 모델이 선택한 ID/status를 유지하고 값 표시만 원본 복사로 바꾸면 22/40이었다. 단순한 포맷 문제와 값 복사 계약 문제를 함께 갖고 있었으며, 이것을 의료 지식의 부족으로 해석하지 않는다.

Qwen3.5-2B의 **조건 추출 방식 200건 확장 검사에서는 195/200**, 평균 2.71초였다. 실패 5건은 모두 한국어 `걷기` 항목 앞의 공백 하나 때문에 `no_records`로 끝났다. 날짜·시간·항목의 양끝 공백만 정리한 사후 재처리에서는 200/200이 됐다. 내부 공백·숫자·기록 값은 바꾸지 않았다. 이것은 오류를 본 뒤 만든 수정이며 새 모델 실행이나 미사용 시험 자료의 결과가 아니다.

필터 방식에서 모델에는 질문만 제공한다. 프로그램이 날짜·시간·항목을 모두 일치시키고, 선택된 환자의 제공 기록에서 값을 그대로 표시한다. 기록 메모의 지시문은 모델이 받지 않으며, 존재하지 않는 값이나 다른 환자 ID를 모델이 만들어 확정하는 경로가 없다. 다만 의료 질문의 분류 정확도나 자유로운 질문 전체의 안전성은 별도 문제다.

### 발견한 실험 연결 문제

초기 Qwen 2B grammar 실행은 모델 종료 토큰 248044와 tokenizer 종료 토큰 248046의 차이를 반영하지 않았다. JSON을 완성한 뒤 줄바꿈을 계속 생성해 40건 모두 160-token 한도에 도달했고 평균 12.63초가 됐다. 모델의 실제 generation EOS를 형식 강제기에 제공하도록 수정하고 회귀시험을 추가했다. 수정 후 실행은 새 ID로 보존한다. 초기 지연을 형식 강제 자체의 비용으로 사용하지 않는다.

초기 grammar 원본은 진단 이력으로 보관하며 채택 비교에는 `grammar-eos-fixed40` 실행을 사용한다. LMFE·Transformers 연결부와 이 호스트 로직의 결과이지 모바일 native grammar runtime의 성능 측정은 아니다.

## OCR: 인식과 표기 차이를 구분

한국어/영어 모델 80장, 다국어 모델 160장을 검사했다. 영어 40장은 두 모델에 공통으로 사용했으므로 서로 다른 입력은 총 200장이다. CPU 4 threads, oneDNN 비활성 조건에서 평균은 각각 2.35초와 2.47초였다.

한국어·영어 CER은 0%였다. 다국어의 초기 CER 차이는 모두 `:`와 `：`의 전각/반각 표기 차이였다. **콜론 너비만 맞춘 보조 CER은 다섯 언어 모두 0%**였다. 숫자·라틴 단위의 대소문자를 구분한 multiset 검사도 각 80/80, 160/160이었다. 이 지표는 용량과 다른 행의 숫자 연결, 모든 의학 단위의 의미를 판정하지 않는다.

공백까지 비교한 원문 전체 일치는 36/80, 40/160이었다. 띄어쓰기·표기 처리와 사용자의 확인 과정이 여전히 필요하다. 위 0%는 공백·대소문자 및 명시한 콜론 정규화를 적용한 단순 합성 인쇄문 결과이며 실제 처방전 정확도가 아니다.

Paddle의 기본 캐시 폴더 생성 오류는 전용 환경의 캐시 경로 패치로 해결했다. 추가로 oneDNN을 켠 비교는 3건 연속 `ConvertPirAttribute2RuntimeAttribute ... pir::DoubleAttribute` 미지원 오류로 중단됐다. 이 설정의 정확도·속도는 미측정으로 남겼다. 학습 대신 먼저 실제 사진과 모바일 실행 엔진을 비교하는 것이 다음 단계다.

## 음성 전사: Whisper small을 모바일 기준선으로

언어별 FLEURS 발화 50건씩, 총 200건을 동일하게 사용했다. 아래 CER은 낮을수록 좋다. 공백·대소문자는 정규화하고 문장부호·소수점은 보존했다. 리더보드 점수나 의료 용어 정확도와 같지 않다.

| 모델 | 한국어 CER | 영어 CER | 일본어 CER | 중국어 원문 CER | 중국어 간체 표시 보조 CER | 발화 평균 시간 | peak GPU 할당 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Whisper base | 36.85% | 6.40% | 28.89% | 38.99% | 21.60% | 0.39초 | 0.17 GiB |
| Whisper small | 12.52% | 5.18% | 17.74% | 24.10% | 13.00% | 0.69초 | 0.52 GiB |
| Qwen3-ASR-0.6B | 11.04% | 4.64% | 15.02% | 13.97% | 13.97% | 2.92초 | 1.69 GiB |

Whisper의 중국어 출력에 번체가 섞여 있어 [OpenCC](https://github.com/BYVoid/OpenCC) 1.4.2 `t2s`로 예측 표기만 간체로 맞춘 사후 지표를 함께 계산했다. 원래 예측과 기본 점수는 보존했다. 표기 변환은 번역이나 약명 의미 검증이 아니다.

이 PC 조건에서 Qwen ASR은 한국어·영어·일본어 CER이 조금 더 낮았으나 평균은 Whisper small보다 약 4.2배 느렸고 GPU 할당도 컸다. 간체 표기를 맞춘 중국어에서는 Whisper small이 조금 낮았다. 표본이 작은 공개 읽기 음성이므로 일반적인 우열이나 임상적 차이를 단정하지 않는다. 모바일 통합 기준선은 small, 품질·용어 사전 힌트 등을 추가 비교할 후보는 Qwen으로 두는 판단이다.

**세 모델 모두 무음 3건에서 비어 있지 않은 전사를 만들었다.** 모델 교체만으로 빈 입력 문제가 해결되지 않았다. 완전 무음 입력 차단, 음성 구간 검출, 원본 청취·미확정 초안 확인이 필요하다. 숫자가 한글 표현에서 아라비아 숫자로 바뀌는 등 표기 차이도 있어, 공개 발화의 숫자 문자열 일치율을 약물 용량 정확도로 해석하지 않는다.

Qwen 최초 실행의 영어 1건에서 61.55초 지연이 관측됐다. 같은 음성을 별도 재실행한 값은 1.33초로 재현되지 않았고 원인은 확정하지 못했다. 다른 두 지연 사례는 재실행에서 7.49초·2.90초였다. 최초 결과를 평균에서 제거하지 않았으며 재실행 3건은 모델 비교에 합산하지 않았다.

## 다음 실행 판단

1. **모바일에서 좁은 기록 조회부터 검증한다.** Qwen 2B 조건 추출 → 필드 경계 공백 정리 → 호스트 검증/조회 → 원문 표시를 첫 프로토타입 방향으로 둔다. 실제 자연어 질문, 상대 날짜, 혼합 질문과 불필요한 보류를 새 자료로 검사한다. 현재 200건의 사후 100%만으로 채택을 확정하지 않는다.
2. **OCR·ASR은 원본과 초안 확인을 중심으로 연결한다.** OCR은 실제 촬영 자료의 반사·잘림·행 연결, ASR은 소음·고령자·약명·숫자·부정·긴 녹음을 먼저 확보한다. 의료 기록을 자동으로 정정하거나 확정하지 않는다.
3. **학습은 반복되는 오류가 확인된 뒤 한다.** 입력·표기·검색·실행 엔진 개선 이후에도 남는 의도/필드 추출에는 소규모 SFT/LoRA, OCR/ASR에는 검수한 도메인 자료를 검토한다. 이번 개발 자료를 학습에 넣고 같은 자료의 점수를 개선 근거로 사용하지 않는다.
4. **증류는 검증된 교사를 확보한 뒤 비교한다.** 교사 정답의 숫자·단위·부정·근거를 검수하고 새 분할에서 학생과 비교한다. 의료 지식을 작은 모델에 외워 넣는 방식으로 승인 근거 검색이나 안전 규칙을 대체하지 않는다.

## 이전 실험의 실패 재분류

기존 8건 비교 원본의 해시를 확인한 뒤 다시 읽었다. 이번 좁은 조회 실험과는 과업이 달라 점수를 직접 비교하지 않는다.

| 이전 후보 | 기대 검사 전체 통과 | 관측 실패 |
|---|---:|---|
| Qwen3.5-4B | 5/8 | 실패 3건에서 기록 참조·도구 순서·최종 상태가 함께 불일치. 필수 JSON 필드 오류는 없었음 |
| Qwen3-4B | 0/8 | 필수 JSON 오류 없이 기록 참조 7건, 최종 상태 8건 불일치. A1에 한국어 원문과 다른 영어 검색어를 만든 사례가 존재 |
| EXAONE 1.2B | 0/8 | 15개 모델 호출에서 schema 오류. out_of_scope_reason, reason_code, completion_conditions 누락 반복 |

`EVIDENCE_NOT_FOUND`를 모두 모델 실패로 세지 않았다. Qwen3.5-4B의 통과 사례 4건에도 근거가 없을 때의 정상 보류가 있었다. 검색과 출력 계약 실패를 의학 지식 부족으로 단정하고 바로 학습을 시작할 근거는 부족했다.

## 결과 해석의 범위

1. 챗봇 개발 자료는 8가지 유형의 반복 변형이다. 날짜·시간·항목이 명시된 짧은 질문이며, 상대 날짜·오타·긴 대화·복합 질문·실제 간병인의 표현을 대표하지 않는다. 개발 결과를 본 뒤 추가한 filter 방식은 몇 개의 예시, 프롬프트, 출력 계약과 호스트 역할을 함께 바꾸었다. 개선 원인을 한 요소로만 설명할 수 없다.
2. 같은 40건끼리 방식/모델을 비교하고 2B filter의 200건 확장 검사는 별도로 표시한다. 이 기준선 실행 당시에는 미사용 held-out 100건을 그대로 남겼다. 이후 [추가 학습·증류 파일럿](ai_training_results_2026-09-11.md)에서 원본/SFT/증류 비교에 사용했다. 이것도 다른 기록·표현을 가진 합성 자료이며 임상 시험 자료가 아니다.
3. OCR 입력은 가로 방향의 단순 합성 문서다. 실제 약 봉투·처방전 사진의 반사·접힘·세로쓰기·복잡한 행 연결·필기 성능을 검증하지 않았다. OCR용 held-out 50장도 이번 비교에 사용하지 않는다.
4. ASR은 일반 읽기 음성이다. 약명·용량·부정·고령자 발음·생활 소음·화자 분리는 별도 검사가 필요하다. FLEURS의 사전학습 포함 여부는 확인하지 못했다. 중국어는 Mandarin/간체 전사이며 번체 표시·방언별 검증은 아니다.
5. PC NF4/FP16/CPU 조건의 시간·메모리를 Android/iOS 성능으로 대입할 수 없다. 실제 사용 기기와 모바일 runtime의 변환·양자화·발열·메모리·취소·잠금·원본 보관 동작을 검증해야 한다. Mac이 없어 iOS 실행 검증은 여전히 남아 있다.
6. 승인된 의료 문서 검색과 약물 상호작용 규칙은 이 비교가 다루지 않았다. 수치 생성 대신 원문을 표시해도 의료 해석의 정확성이 증명되는 것은 아니다. 앱의 의료 답변은 계속 비활성 상태로 둔다.

## 코드·실행 검증

새 도구는 다운로드/자료 준비, 공통 무결성 검사, 모델 어댑터, 필터 조회, 채점, 실행, 집계로 분리했다. 모델 어댑터에는 평가 정답을 전달하지 않는다. Python 테스트 117개가 통과했고, 수치·단위·부정·다른 ID·파일 변조·불완전 결과·종료 토큰 불일치·필터 공백·표기 변환을 검사했다. `git diff --check`도 통과했다.

전체 실행의 Python 소켓 audit 기록에 네트워크 시도는 없었다. 다운로드 단계와 추론 단계를 분리했으며 환자 자료를 사용하거나 외부 학습 서비스에 전송하지 않았다. 이 검사는 native 라이브러리의 패킷 캡처나 모바일 앱 네트워크 검증을 대신하지 않는다. 앱 코드가 바뀌지 않아 Flutter/실기기 시험은 이번에 반복하지 않았다.
