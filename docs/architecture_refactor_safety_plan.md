# 구조 개선의 실패 시나리오와 완료 조건

2026-09-10. `caregiving_notebook_requirements.md`와 `architecture_review_2026-09-10.md`를 기준으로, 구현 전에 정의한다. 기능·화면의 의미, 암호화 방식, 기존 사용자 원문과 의료 기능 비활성 상태를 유지한다.

| ID | 실패 시나리오 | 구현 및 회귀시험의 완료 조건 |
|---|---|---|
| ARCH-01 | 비동기 콜백의 일부 저장 후 실패로 초안 소실 | 공개 저장 API는 콜백 대신 불변 요청 데이터를 받는다. 기록 확정·초안 삭제는 짧은 동기 트랜잭션 하나이며 실패 시 둘 다 원복된다. |
| ARCH-02 | 화면/AI가 세션·잠금 상태를 바꾸거나 원시 DB/키에 접근 | 세션은 읽기 전용, 저장소와 플랫폼은 private. presentation의 infrastructure import 및 db/vault/mutate 접근을 구조 검사로 차단한다. |
| ARCH-03 | 환자 전환·잠금·삭제 후 늦게 도착한 결과 표시/저장 | 작업 범위는 환자와 세션 세대에 고정한다. 전환 후 기존 범위가 무효이며 읽기 인터페이스에 쓰기·식별정보 API가 없다. |
| ARCH-04 | 이전 형식 또는 잘못된 초안 하나가 목록 전체를 막음 | 이전 payload를 읽고 새 payload는 버전을 기록한다. 잘못된 항목은 원문을 보존한 개별 복구 항목으로 표시한다. 작성 중 빈 입력은 허용한다. |
| ARCH-05 | 모델/화면이 전달받은 Map/List를 수정하여 조회 상태 변조 | 생성자 입력·중첩 필드·직렬화 결과에 대한 별칭 변경을 차단한다. |
| ARCH-06 | DB 스키마 변경 시 기존 선택 백업 거부 | 독립된 백업 문서 버전/codec을 사용하고 현재 format 2/schema 3 fixture를 복원한다. 알 수 없는 버전은 현재 데이터 변경 없이 거부한다. |
| ARCH-07 | 모듈 분리 중 환자 범위·수정 충돌·복약 이력·복원 원자성 손실 | 기존 SQLCipher 및 전체 기능 테스트를 유지한다. 트랜잭션 조정자는 공유하고 각 기능은 명시적인 인터페이스로 조립한다. |
| ARCH-08 | 관계없는 변경마다 사진 정리/알림 전체 갱신 | 기능별 변경 영향을 전달한다. 메모/대화 저장은 알림 계산을 유발하지 않고 복약·일정 변경은 알림을 갱신한다. |
| ARCH-09 | 플랫폼 구현 누락이 빈 성공으로 처리 | 필수 작업을 추상 계약으로 만들고 fake에만 명시적 동작을 둔다. |
| ARCH-10 | 번역 문장 변경 때문에 오류/상태 분기 변경 | 안정된 오류 코드·초안 상태 enum을 제공하고 표시 문장은 번역 계층으로 이동한다. 기존 5개 언어와 원문 보존 검사를 통과한다. |
| ARCH-11 | Python 역할·backend·채점 분리로 실험 결과/해시 변경 | 프롬프트·모델·계약은 변경하지 않는다. 역할 단계와 runtime/채점을 나누고 공통 직렬화의 기존 bytes/hash 호환성을 시험한다. fixture/replay 테스트를 모두 실행한다. |

순서: 불변 데이터·저장 요청·초안 codec → 세션/기능 서비스·저장소 모듈 → 화면 연결 및 갱신 범위 → 백업 호환 → Python 분리 → 전체 분석·테스트·Android 빌드 → 해결 내역 대조.

실제 사용자 저장소를 시험 데이터로 사용하지 않는다. 이전 백업 fixture는 합성 데이터로 구조 변경 전에 생성한다. Android 빌드는 새 APK를 생성하며 연결된 휴대전화에 자동 설치하지 않는다. iOS 실행 검증은 Mac/Xcode가 필요하므로 Windows 정적 검증과 구분한다.
