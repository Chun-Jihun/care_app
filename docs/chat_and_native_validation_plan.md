# 대화창과 네이티브 기능 — 구현 전 시험 계획

기준: `caregiving_notebook_requirements.md` 전체와 2026-09-07 사용자 요청. 대화 UI만 추가하며 AI 답변이나 의료 판단은 생성하지 않는다. 실제 플랫폼 기능은 대역 시험과 구분해 검증한다.

| ID | 실패 시나리오 | 구현 전 정의한 시험 |
|---|---|---|
| CHAT-01 | AI가 없는 상태에서 답변한 것처럼 보임 | 사용자 질문만 저장, 고정된 연결 상태 표시, 생성 응답·출처·자동 전송 없음 |
| CHAT-02 | 질문이 다른 환자의 수첩에 노출 | 환자별 조회·삭제 범위, 전환 시 입력창 초기화, 잠금 시 대화 UI 제거 |
| CHAT-03 | 선택하지 않은 보관 정책 또는 만료된 내용이 남음 | 첫 사용에 보관 방식 선택, 이번 잠금 해제 동안만/7일/30일/직접 삭제 시까지, 만료 후 조회·백업 제외, 보관 중단 시 기존 대화 삭제 확인 |
| CHAT-04 | 업데이트·복원 시 일기 또는 대화 손실 | v1→v2 암호화 백업 후 트랜잭션 migration, 기존 일기 보존, 대화 재시작·암호화 백업 복원, 환자 삭제 cascade |
| CHAT-05 | 작성 내용을 임의로 간병일기에 반영 | 질문을 진료 준비에 옮길 때 편집 화면에서 사용자 저장 확인, 자동 반영 없음 |
| NATIVE-01 | 촬영 취소·실패를 첨부 성공으로 표시 | 별도 시험용 Android 에뮬레이터의 가상 카메라로 촬영·취소, 첨부 열기·재실행, 원본 캐시 정리 |
| NATIVE-02 | 알림 허용·거부·취소가 실제 OS와 다름 | Android 권한 거부/허용, OS 예약 및 실제 게시 확인, 해제·할 일 완료 시 예약 제거, 잠금 내용에 기록 원문 없음 |
| NATIVE-03 | 취소·잘못된 인증으로 잠금 해제 | 시험용 에뮬레이터에만 PIN/지문 설정, 인증 성공·취소·미등록 상태, 백그라운드 잠금 및 재인증 |

실제 휴대전화가 연결되지 않았다면 에뮬레이터 검증이라고 표시한다. 호스트 웹캠 대신 가상 장면을 사용한다. 사용자 휴대전화의 잠금 설정을 변경하거나 기존 데이터를 삭제하지 않는다. iOS는 Mac/Xcode와 장치가 제공되지 않으면 자동 검증으로 대체했다고 표현하지 않는다.

## 네이티브 실행 중 추가된 회귀 사례

- Android release에서 알림 아이콘이 리소스 축소로 제거되면 초기화와 권한 요청까지 실패한다. release APK 리소스 테이블에 `drawable/ic_notification`이 남는지 확인하고 OS 권한 거부·허용과 예약 알림 표시를 재검증한다.
- 중첩 Navigator의 Android 시스템 뒤로가기가 앱을 종료하면 사진 상세에서 기록 화면으로 돌아올 수 없다. 위젯의 `handlePopRoute`와 에뮬레이터 KEYCODE_BACK으로 회귀 검증한다.
- Android의 기본 시간대 ID `GMT`가 축약 시간대 DB에 없어 알림 초기화가 실패하는 현상을 재현했다. 전체 IANA 별칭 DB에서 GMT·Asia/Seoul을 검사하고 기기의 알림 흐름을 다시 실행한다.
- OS 인증 취소를 저장 공간 오류로 표시하지 않는다. 취소·미등록·OS 인증 실패는 인증 실패로 반환하고 PIN 대안을 유지한다.
- 잠금 중 루트 Navigator의 삭제 확인창·날짜 선택창이 남으면 사적인 UI가 재노출될 수 있다. 확인창을 연 상태에서 잠글 때 대화상자가 사라지는 회귀시험을 정의하고 모든 인증 후 대화상자를 인증된 Navigator에 연결한다.
