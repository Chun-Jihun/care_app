## 검증 방법

- 합성 데이터만 사용한 저장소·컨트롤러·위젯 테스트 및 Flutter 정적 분석.
- Android 빌드 및 가능한 로컬 에뮬레이터 재실행 검증. iOS 실행 검증은 Mac 부재로 수행할 수 없다.
- 초안의 마지막 입력 직후 OS가 프로세스를 즉시 강제 종료하면 아직 자동 저장하지 않은 부분은 복구를 보장할 수 없다. 저장 완료 상태와 실제 복구 범위를 구분한다.

## 실제 동작

- 초안 대상: 10종 일기, 약 목록·처방 지시 편집, 실제 복약, 할 일, 진료 준비, 간병인 상태. 프로필의 식별정보, PIN·백업 비밀번호, 대화 입력창, 사진 촬영은 대상 밖이다.
- 첫 사용 시 보관기간을 선택한다. 7일·30일·직접 삭제 중 선택이며 마지막 저장 시각부터 계산한다. 선택 전 보관기간을 임의 지정하지 않는다. 만료 초안은 조회에서 제외하고 저장소 열기·갱신·기간 변경·백업 시 삭제한다.
- 입력을 400ms 지연해 저장하고 잠금 전에 동기 저장한다. 암호화 완료 또는 실패 상태를 표시한다. 뒤로 가기는 계속 작성·초안 삭제·초안 보관 후 나가기를 구분한다.
- 잠금 후 홈에서 해당 수첩의 초안과 환자에게 속하지 않는 간병인 상태 초안을 찾아 이어 쓴다. 확정 저장과 초안 삭제는 같은 트랜잭션이다. 삭제·만료된 초안이나 이전 잠금 세션의 늦은 저장으로 초안을 부활시키지 않는다.
- 수정 대상이 바뀌거나 삭제되면 초안 내용을 읽을 수 있도록 남기되 자동 덮어쓰기를 차단한다. 복약 초안도 당시 약 버전을 확인한다. 새 진료 준비가 선택했던 원본을 삭제하면 저장 시 연결 오류를 표시하고 해당 선택을 사용자가 해제해야 한다.
- 백업의 기간은 시작일 00:00 이상부터 종료일 다음 날 00:00 미만까지 기기의 현지 시각으로 계산한다. 일기 시각·할 일 예정일·진료 준비/대화 작성일·간병인 상태 기록일을 필터링한다. 약 목록과 모든 처방 계획, 수첩 배경, 포함한 일기의 수정 이력은 기간 밖이어도 함께 포함한다.
- 선택한 진료 준비가 기간 밖 원본을 참조하면 해당 연결을 제외하고 재검토 상태로 복원한다. 메모에 직접 적힌 이름·기간 밖 사실까지 자동 마스킹하는 기능은 아니다.
- 새 백업은 선택 행과 선택 사진만 포함한다. DB·파일 마스터 키와 제외한 원본 DB 페이지를 내보내지 않는다. 사진은 사진별 키와 함께 비밀번호로 보호되는 파일 안에 담고 복원 때 새 ID·키로 다시 암호화한다.
- 선택 복원은 현재 수첩·초안·설정을 보존하고 `(복원)` 표시가 있는 별도 수첩을 추가한다. 중복 검사는 백업 ID와 실제 남아 있는 추가 수첩·간병인 상태의 ID로 한다. 일부만 삭제한 상태의 재복원은 중복 차단하고, 추가한 항목을 모두 삭제하면 다시 복원할 수 있다. 기존 수첩 병합이나 항목별 충돌 해결은 구현 범위 밖이다.
- 복원한 수첩의 알림은 설정에서 검토 후 명시적으로 켠다. 처방 시각과 할 일의 원래 값은 변경하지 않는다. 대화 만료일도 연장하지 않는다.
- 이전 전체 백업 format 1은 기존과 같이 전체 교체하며 UI에서 현재 초안까지 교체된다는 별도 확인을 받는다. 새 format 2는 행·열 허용 목록, 데이터 타입, 날짜, 환자·원본 연결, 수정 이력, 사진 인증을 검사한 뒤 새 저장소 세대를 커밋한다. 외부 전송·클라우드 동기화는 추가하지 않았다.

## 구현 위치

- `mobile/lib/application/draft_session.dart`: 작성 화면의 자동 저장 타이머와 세션 수명.
- `mobile/lib/infrastructure/database_drafts.dart`: v3 마이그레이션, 초안 보유기간·확정 트랜잭션.
- `mobile/lib/infrastructure/database_backup.dart`: 선택 범위와 의존 기록, 새 ID로 추가 복원.
- `mobile/lib/infrastructure/selective_backup.dart`: 비밀번호 암호화, 사진 검증, 새 저장소 세대 커밋.
- `mobile/lib/presentation/draft_page.dart`, `backup_page.dart`: 초안 목록·재개와 백업 선택·검토 화면.

## 검증 결과 (2026-09-07)

- Flutter 자동 시험 **47개 통과**. 기존 34개에 저장소/컨트롤러 9개, 화면 4개를 추가했다. 최대 허용 길이의 한글 증상 기록이 초안으로도 저장되는지 포함한다. 초안 payload 한도는 UTF-8 256KB다.
- Flutter 정적 분석: 문제 없음. Android release APK 빌드 성공. 별도 배포 키 서명을 구성한 스토어 산출물은 아니다.
- 저장소 시험: 실제 SQLCipher v1/v2 → v3 갱신, 재개방 후 초안 복구, 확정 저장과 초안 삭제의 원자성, 수정·처방 충돌, 환자 격리, 만료·삭제 후 부활 차단, 선택 백업에서 제외 표식 부재, 약/진료/수정 이력/사진 재연결, 원본 보존, 중복 복원 및 추가 사본 전부 삭제 후 재복원, 잘못된 비밀번호·변조·잘못된 날짜 타입·누락된 사진·허용하지 않은 테이블·커밋 취소 시 원본 보존을 확인했다.
- 화면 시험: 앱 재시작 후 메모·복약 초안 재개와 저장, 복용 상태·기록 시각 유지, 삭제된 진료 원본의 명시적 연결 해제, 백업 선택→비밀번호 확인→추가 복원 흐름, 320×640 화면과 1.5배 글자에서 백업 확인 대화상자를 검증했다. PIN·백업 비밀번호는 초안에 저장되지 않는다.
- Android 15/API 35 `care_validation`: 기존 앱을 데이터 유지 방식으로 업데이트하고 PIN으로 저장소를 열었다. `NATIVE_DRAFT_RECOVERY_TEST`를 입력해 자동 저장 안내를 확인한 뒤 `am force-stop`으로 종료했다. 재실행 전후 미확정 초안은 오늘의 기록 수(1개)에 포함되지 않았다. 초안 재개 시 같은 문구와 2026.09.07 13:42 시각을 확인했다. 저장 후 초안 목록이 비었으며 일기에 해당 기록이 한 번만 추가됐다. 기존 `NATIVE_CAMERA_TEST`와 114KB 첨부 연결도 유지됐다. 모두 기존 시험용 가상기기의 합성 데이터다.
- Android의 새 파일 선택기를 통한 실제 선택 백업 파일 왕복과 실물 기기의 저장 공간 부족·전원 장애·메모리 압박은 이번 네이티브 시험에 포함하지 않았다. 백업 화면 시험의 OS 파일 선택기는 대역을 사용한다. iOS는 Mac/Xcode 부재로 실행 검증하지 못했다.
