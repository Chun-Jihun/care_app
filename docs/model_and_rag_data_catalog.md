## 1. 문서 목적

이 문서는 모델을 파인튜닝하거나 RAG 검색에 넣거나 성능 평가에 사용할 **실제로 공개된 데이터와 공식 정보원**을 구분해 기록한다. 단순 후보 목록이 아니라 다음 질문에 답할 수 있어야 한다.

- 무엇을 학습시키거나 검색할 것인가?
- 의료 사실, 도구 사용 행동, OCR, 평가는 서로 분리되어 있는가?
- 공개 위치, 규모, 언어, 접근 조건과 라이선스는 무엇인가?
- 어떤 검수와 승인이 끝나야 제품에 넣을 수 있는가?
- 학습 데이터가 동결 평가 세트에 섞이지 않는가?

이 목록에 있다는 사실은 곧 사용 승인을 뜻하지 않는다. `도입 후보`는 권리 검토와 의료진 검수를 거쳐 `승인 스냅샷`이 된 뒤에만 제품 RAG 인덱스나 학습 파이프라인에 들어갈 수 있다.

## 2. 데이터 역할과 도입 원칙

### 2.1 역할 분리

| 역할 | 학습·저장할 내용 | 넣지 말아야 할 내용 |
|---|---|---|
| SFT·LoRA | 도구 선택, JSON 스키마, 기록 구조화, 쉬운 한국어, 근거 인용 형식, 불확실할 때 확인·보류하는 행동 | 약의 용량·상호작용·위험 임계값을 모델이 외워서 판단하게 하는 의료 사실 |
| 에이전트 RL | 허용된 모의 환경에서 읽기 전용 도구를 선택하고 실패를 복구하는 행동 | 실제 환자 데이터, 약 변경·진단·치료 결정, 외부 전송 또는 쓰기 권한 도구 |
| OCR·VLM 학습 | 약 포장·문서의 글자 영역과 필드 후보 추출 | 사진만으로 약 또는 음식의 안전성을 확정하는 라벨 |
| RAG | 발행기관과 버전이 명확하고 의료진이 검수한 원문 근거 | 일반 웹 검색 결과, 출처가 추적되지 않는 QA, 자동 생성 요약문 |
| 규칙 엔진 | DUR 금기·주의, 응급 연락, 환자별 의료진 지정 조건처럼 결정적으로 처리할 항목 | LLM이 자유 생성한 임계값 또는 규칙 |
| 평가 | 출시 차단 조건과 비교 지표를 재현하는 동결 문항 | 학습 또는 프롬프트 조정에 사용한 항목 |

### 2.2 의료 사실을 파인튜닝보다 RAG에 두는 이유

- 의약품 허가정보와 주의사항은 개정될 수 있어 가중치보다 버전이 고정된 문서·구조화 데이터로 관리해야 한다.
- 모델이 무엇을 근거로 말했는지 문장·페이지 수준에서 추적해야 한다.
- 잘못된 문서는 인덱스에서 철회할 수 있어야 하며 모델 전체를 다시 학습하지 않아야 한다.
- 약물 용량, 상호작용, 금기와 위험 임계값은 생성형 답변이 아니라 규칙 엔진과 구조화 조회가 우선해야 한다.

공개 도구 데이터로 먼저 배울 것은 의료 지식이 아니라 `도구를 불러야 하는지`, `어떤 읽기 도구인지`, `필수 인자가 부족하면 무엇을 물을지`, `스키마를 지킬지`이다. 실제 앱의 도구명과 정책은 공개 데이터에 없으므로 마지막 단계에는 의료진과 개발자가 만든 앱 전용 합성·검수 데이터가 필요하다.

[CAST 논문](https://arxiv.org/abs/2605.15041)은 비교할 학습법이지만, 조사일 현재 논문에서 공식 코드·학습 데이터·결과 체크포인트 링크를 확인하지 못했다. 따라서 이 카탈로그의 `실제 확보 가능한 데이터`로 계산하지 않으며, 공개 자료나 재현 가능한 데이터 생성 절차가 확인된 뒤 별도 리비전으로 등록한다.

## 6. 오염 방지와 분할 규칙

1. 원본 데이터의 공식 train·validation·test 구분을 보존한다.
2. BFCL V4 동결 데이터, AgentBench FC test, ToolBench test/eval과 프로젝트 frozen test의 해시를 `do-not-train` 목록에 등록한다.
3. 같은 질문의 번역·의역·도구명 치환·합성 변형도 원본과 같은 그룹으로 묶어 다른 split에 보내지 않는다.
4. 파인튜닝 전 모든 샘플을 평가 세트와 정규화 문자열·MinHash·임베딩 유사도로 대조하고 의심 항목은 제외한다.
5. 공개 모델의 사전학습 오염 여부를 알 수 없으면 암기형 점수보다 실행 결과, 근거 대조와 프로젝트 신규 문항을 우선한다.
6. 평가 세트는 모델 선택·프롬프트 조정·검색 임계값 조정에 사용하지 않는다.
7. 데이터셋 리비전, 파일 해시, 필터 코드와 제외 건수를 실행 명세에 남긴다.

## 8. 도입 절차와 승인 상태

```text
discovered
  → rights_reviewed
  → technically_validated
  → clinician_reviewed
  → approved_snapshot
  → indexed_or_trained
  → monitored
  → superseded_or_revoked
```

- `discovered`: 이 문서에 실제 후보와 링크만 등록한 상태
- `rights_reviewed`: 상업 이용, 변경, 재배포, 표시와 제3자 권리를 확인한 상태
- `technically_validated`: 스키마, 누락, 중복, 인코딩, 업데이트와 품질 표본 검사를 통과한 상태
- `clinician_reviewed`: 허용할 주장·금지할 주장·적용 범위를 의료진이 승인한 상태
- `approved_snapshot`: 원문 파일·API 응답·해시와 메타데이터를 한 버전으로 봉인한 상태
- `indexed_or_trained`: 승인된 목적과 split에만 사용한 상태
- `superseded_or_revoked`: 개정·오류·허가 변경으로 검색과 학습 파이프라인에서 제외한 상태

외부 API가 갱신되어도 운영 인덱스에 자동 반영하지 않는다. 새 응답은 격리된 staging에 받고 변경 비교, 권리 확인, 의료 검수와 회귀시험을 통과한 뒤 새 승인 스냅샷으로 승격한다.

## 9. 첫 데이터 구축 우선순위

첫 에이전트 실험의 다운로드 범위와 순서는 [`로컬 간병 에이전트 구성 및 성능평가 계획`](./agent_architecture_and_evaluation_plan.md#12-실험-준비와-다운로드-계획)을 우선 적용한다. 공개 AgentBench·BFCL·ToolBench 점수를 재현하기 위한 데이터는 초기 간병 도메인 실험의 선행조건이 아니다.

1. **간병 도메인 평가 기준선**: 외부 데이터보다 먼저 간병일기 구조, 비식별 합성 기록과 DS-DIARY·DS-STRUCT·DS-AGENT 파일럿을 설계한다.
2. **약 정보 파일럿**: 첫 텍스트 도메인을 복약 기록과 일반 약 정보 이해로 제한하고, e약은요의 소규모 원본 스냅샷을 만든다.
3. **구조화 안전 데이터**: DUR은 자유생성 RAG가 아니라 규칙·구조화 조회 실험에 필요한 범위만 별도 스냅샷으로 준비한다.
4. **동일 모델 구조 비교**: Qwen3.5-4B 하나로 단일 에이전트와 역할 분리 구성을 먼저 비교해 모델 차이와 구조 차이를 섞지 않는다.
5. **추가 모델 필요성 결정**: 첫 오류 분포를 확인한 뒤 Qwen3-4B, MedGemma 1.5 4B 또는 Nanbeige 중 필요한 후보만 추가한다.
6. **학습 필요성 결정**: zero/few-shot 프로젝트 기준선이 앱 전용 도구·구조화 출력 게이트를 못 넘을 때만 xLAM 60k 일부와 앱 전용 검수 샘플을 이용한 LoRA를 검토한다.
7. **음식·OCR·질환 확장**: 첫 텍스트 실험을 마친 뒤 식품영양성분DB, AI Hub OCR과 질환별 문서를 각각 별도 계획으로 준비한다.

따라서 초기에는 AgentBench, BFCL, ToolBench, xLAM 60k, APIGen-MT-5k와 AI Hub 헬스케어 QA 전체를 일괄 다운로드하지 않는다.

## 10. 아직 결정해야 할 사항

1. 첫 질환·치료 단계 콘텐츠 팩과 검수 책임 의료진
2. 앱의 상업·비상업 배포 계획과 CC BY-NC·공공누리 제4유형 데이터를 연구 비교에만 둘지 여부
3. 목표 장비와 실제로 감당할 수 있는 LoRA·AgentRL 학습 자원
4. 외부 공공 API를 실시간 호출할지, 승인된 오프라인 스냅샷만 배포할지. 첫 A1~A5 실험은 [`역할·도구 사용 규약`](./agent_role_and_tool_contracts.md)에 따라 승인된 로컬 스냅샷만 사용한다.
5. API 장애·개정 시 마지막 승인 스냅샷의 유효기간과 사용자 표시 방식
6. AI Hub 데이터 신청 주체, 이용정책 검토, 안심존·IRB·모델 반출 절차
7. 실제 처방전·약 봉투·간병기록의 동의, 비식별화, 보유기간과 폐기 책임자
8. 공개 데이터의 한국어 품질·의료 정확성 표본 검수 규모와 탈락 기준
9. 데이터셋·문서·인덱스·모델의 리비전과 해시를 보관할 로컬 레지스트리 형식

A1~A5의 앱 전용 읽기 도구 목록과 LLM-facing JSON은 [`A1~A5 역할·도구 사용 규약`](./agent_role_and_tool_contracts.md) `v0.1.0`에서 결정했다. A6 OCR·VLM과 DUR 구조화 규칙 도구는 후속 계약으로 남아 있다.
