## 기준과 범위

## 판단

AI 없이 사용하는 간병수첩의 기본 구조는 제품 의도에 맞는다. 화면·업무 처리·암호화 저장 계층이 나뉘어 있고, 실제 복약과 처방 지시 이력도 분리되어 있다. 다만 잠금 이후 비동기 처리, 알림 재예약, 저장소 전환, 입력 유실에서 실제로 고쳐야 할 문제가 있었다. 이번 변경으로 기본 프레임의 안정성과 유지보수성을 개선했다. 제품 전체의 의료 기능이나 출시 검증을 완료했다는 뜻은 아니다.

## 구조·보안 검토 범위와 유지한 설계

- **모바일:** `lib`의 15개 Dart 파일을 모두 읽고 Android/Kotlin·iOS/Swift·manifest·키 저장·빌드 설정·시험을 확인했다. 단순한 `ChangeNotifier`와 SQL 저장 계층을 유지하고, 중복 작업 제어만 공통화했다. 별도 상태관리 프레임워크나 서버를 추가하지 않았다.
- **암호화:** SQLCipher 사용 여부 확인, 서로 다른 의료·식별정보 키, SQL 바인딩, 환자 범위 검사, AES-GCM 인증, 임의 nonce/키, 백업 비밀번호 검증, 자동 백업 제외 설정을 확인했다. 실제 DB 재개방·잘못된 키·변조·사진 삭제·복원은 기존 시험을 유지했다. 복호화는 앱 사용 중 메모리에서 필요하므로 메모리에 평문이 전혀 없다는 주장은 하지 않는다.
- **데이터 무결성:** 의료·식별정보를 연결한 원자적 트랜잭션, 처방 지시의 이전 버전, 실제 복약의 당시 계획 연결, 수정 충돌 검사, 삭제 대기 파일을 유지했다. 이를 단일 JSON 파일이나 공통 문자열 테이블로 단순화하면 필요한 보존·범위 보장이 약해지므로 변경하지 않았다.
- **네트워크:** 빌드한 release APK의 permission 목록에 INTERNET 권한이 없음을 확인했다. 모바일에 외부 LLM·광고·분석 SDK나 자동 의료정보 전송 경로를 추가하지 않았다. 시스템 파일 선택기로 사용자가 저장하는 암호화 백업은 별도 사본이다. APK 권한 검사는 전체 OS·타사 키보드·시스템 앱의 통신을 검사한 것은 아니다.
- **프로젝트 Python 도구:** 19개 파일, 14,044줄, 382개 함수의 AST·입출력 및 위험 API 패턴을 점검했다. 데이터 수집/정제/승격, 시나리오 생성, tool host, 로컬 모델 로더, 실행·보고서의 경계 조건을 집중 검토하고 전체 기존 시험을 실행했다. 모든 함수에 대해 전 경로 검증이나 GPU 모델 실험을 수행한 것은 아니다.
- **의료 평가 경계:** 환자 범위를 host가 결정하는 검사, 역할별 도구 허용 목록·호출 예산, 로컬 모델 파일 해시와 `local_files_only`/`trust_remote_code=false`, staged와 approved 구분, 미검수 결과를 의료 출시 성능으로 승격하지 않는 보고 조건을 확인했다. 모델·프롬프트·검색 인덱스는 변경하지 않았다.
- **외부 benchmark:** `MedAgentBench`의 실행·HTTP 진입점은 점검했지만 외부 원본 전체를 제품 코드와 같은 수준으로 검증한 것은 아니다. 모델 가중치·SDK·생성 데이터도 전체 소스 검토 범위에 포함하지 않았다.

보안 항목의 분류에는 [OWASP MASVS](https://mas.owasp.org/MASVS/), 접근성 시험에는 [Flutter 접근성 지침](https://docs.flutter.dev/ui/accessibility)을 참고했다. 이 검토는 보안 인증이나 법률 적합성 판정이 아니다.

| 사용자 검증 | 글자 확대 시험은 통과했지만 TalkBack/VoiceOver와 실제 가족간병인 사용성 시험은 없음 | 화면 낭독·조작 순서·색 대비·고령 사용자 핵심 과업 시험 |
| 공급망 | 의존성의 알려진 취약점 전체, 네이티브 바이너리·SDK의 보안 감사는 미실시 | 배포 전 잠긴 의존성 목록 기준 SCA/SBOM 및 서명 검증. 이번 변경에서는 검증 없이 일괄 버전 업그레이드하지 않음 |
