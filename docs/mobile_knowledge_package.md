## 설치·검색·챗봇 연결 구현

### 설치와 버전 관리

- `scripts/build_knowledge_delivery.py`가 검증된 구성 9개 파일을 `CAREKB01` 헤더, 길이가 제한된 배포 명세, 원문 파일 순서로 묶는다. 현재 파일은 `data/knowledge-preview/caregiver-essentials-v2.careknowledge`이며 **44,861,812바이트**다. 전송 포장만 추가했으며 실제 자료 42.78MiB는 바뀌지 않았다.
- 앱에 포함한 `mobile/assets/knowledge/releases/`의 버전별 명세와 입력 파일 명세가 바이트 단위로 같아야 한다. 크기·모든 파일 해시 검증 뒤에만 DB를 연다. 임시 폴더 → 고정 버전 폴더 → 활성화 기록의 순서로 확정하므로 설치 실패·취소·미완료 활성화는 기존 버전을 바꾸지 않는다. 정상 이전 버전으로 되돌릴 수 있으며 이전 인용을 위해 확정 버전은 자동 삭제하지 않는다.
- 설정의 **의료 근거 자료** 카드에서 버전·용량·무결성 오류·재확인 기한을 표시한다. 개발 빌드에서는 파일 설치와 개발용 검색을 사용할 수 있다. 배포 빌드의 승인 목록은 비어 있고 미검수 자료의 설치·검색·의료 답변 사용은 차단한다. 재확인 기한은 기술적 갱신 안내이며 임상 검수일을 대신하지 않는다.
- 새 버전은 새 파일명으로 명세를 추가한다. 이전 명세를 함께 유지해야 이전 버전 복구와 과거 인용 열람이 가능하다. 철회한 명세는 앱 허용 목록에서 제외한다. 현재 인증 방식은 **앱에 고정한 해시 허용 목록**이며 원격 업데이트 서버, 서명 키 배포 또는 인터넷 최신 버전 조회를 구현한 것은 아니다.

### 검색과 의료 승인 경계

- 개발용 `KnowledgeSearch`는 낙상·삼킴·식사·간병 부담·퇴원 등 한국어 일상 표현을 명시적인 한국어/영어 검색어로 확장한다. FTS 본문과 문서 제목을 검색하고 본문·제목 일치 수로 재정렬한다. 긴 PDF 본문은 제한된 줄 묶음으로 표시하며 정확한 UTF-16 시작 위치와 전체 원문 페이지를 함께 제공한다.
- 실제 자료의 낙상, 간병 부담, 식사·삼킴, 퇴원 질문에서 관련 자료와 원문 위치를 확인했다. 욕창 질문은 현재 선택 자료에서 근거를 찾지 못했다. 검색 결과가 있다는 사실만으로 환자별 적용 가능성이나 의료 정확성을 승인하지 않는다. 이는 **동의어 기반 키워드 검색 기준선**이며 학습한 임베딩을 사용하는 의미 검색이나 임상 검색 KPI 달성을 뜻하지 않는다.
- 제품 식별은 품목코드 또는 공백·영문 대소문자만 정규화한 전체 제품명으로 수행한다. 부분 이름은 최대 20개 후보와 잘림 여부를 반환하며 자동 확정하지 않는다. 실제 `타이레놀` 부분 이름 시험에서는 7개 후보를 확인했다. DUR 조회 결과가 없거나 제품을 특정하지 못한 경우 안전 판정을 만들지 않는다.
- `ReviewedKnowledgeCatalog`는 설치 승인과 별도로 앱에 등록한 검수 질문·원문 발췌 목록을 확인한다. 운영 목록은 **0건**이다. 향후 검수된 질문의 동등 표현과 함께 검수한 근거 묶음만 생성 후보가 될 수 있다. 일반 검색의 관련도 점수만으로 의료 답변에 승격하지 않는다. 약물 병용·용량·중단·치료 변경은 이 문서 생성 경로에서 보류한다.

### 챗봇과 인용

- `AiService`가 기존 응급·환자 경계 검사를 먼저 수행하고 식별정보를 마스킹한 질문만 `MedicalAnswerService`로 전달한다. 승인 목록·검수 기한·근거 묶음·원문 위치가 모두 확인된 뒤 `DeviceAiRuntime.selectEvidence` → 로컬 `LocalChatEngine` 경로로 최대 3개 발췌를 전달한다.
- 초기 모델 역할은 근거 ID 선택이다. 자유 의료 설명·번역을 표시하지 않는다. 모델이 새로운 문장/키/출처를 반환하거나 함께 검수한 조건 문장을 누락하면 보류한다. 답변은 검증된 원문 발췌이며 검수 만료·충돌·근거 부족을 구분해 안내한다. 생성 후 승인과 원문을 다시 확인한다.
- 답변과 `근거 보기`의 의료 근거 카드는 저장된 발췌를 그대로 신뢰하지 않고 당시 패키지/본문 해시·출처·페이지·시작 위치를 다시 확인한다. 승인 목록에 없는 발췌나 삭제/변조된 자료는 표시하지 않는다. 원문 페이지에서 문맥·발행기관·발행/개정일·검수일·원문 링크를 확인한다.
- 인용은 기존 암호화 대화 보관 정책을 따르며 선택 백업과 복원에서도 원래 패키지 ID를 유지한다. 백업 문서 v5가 인용/보류 사유를 추가하고 v1~v4 및 기존 레거시 백업 읽기는 유지한다. 의료 자료 본문 전체를 개인 백업에 넣지 않는다.
- 합성 승인 fixture로 설치 → 질문 → 제한된 모델 포트 → 답변 저장 → 원문 버튼까지 검증한다. 실제 수집 원천은 계속 미검수이며 의료 생성에 전달하지 않았다. 이번 검증의 모델 출력은 시험용 selector를 사용했다. **현재 학습 모델의 이 새 프롬프트에 대한 선택 성공률·지연시간, 임상 검수, 실제 기기 성능은 별도 검증 과제**다.

v2 약물 형식은 원본의 **필드 값 자체**를 중복 제거하고, 최대 128개 값과 최대 512개 행을 각각 묶어 압축한다. 품목별 양방향 행 목록은 정렬된 ID 차이를 가변 길이 정수로 저장해 행마다 발생하던 DB/해시 색인 비용을 줄였다. 재구성 시 원문 필드명과 값·자료형·null·빈 문자열을 그대로 복원한다. 동일 성분이라는 이유로 다른 제품이나 조건을 합치지 않는다. 모든 레코드와 출처 위치를 다시 복원한 스트림 해시를 입력 스트림과 비교한다. Dart는 조회한 묶음만 해제하며 값 캐시는 압축 해제 바이트 기준 4MiB를 목표로 제한한다(단일 블록 상한 16MiB는 별도).

미리보기에서는 구성 루트 대신 `.../mobile-core-v2-small/dur` 또는 `.../documents`처럼 **개별 패키지 폴더**를 연다. 약물 905,129건의 포함 내용 전체 복원 검증을 통과했다. 선택 문서의 30개 본문/페이지와 HTML 그림 6개는 이전 보존용 패키지와 전부 바이트가 같다. 실제 네 패키지를 Dart에서 열어 조회와 근거 연결을 확인했다. 전체 설치 파일 및 모델까지 작아졌다는 의미나 임상·실기기 검증 완료를 뜻하지 않는다.

축소 작업의 최종 자동 시험: Python 74개 중 72개 통과(기존 선택 의존성 시험 2개 제외), Flutter 관련 시험 24개 통과, 정적 분석 문제 없음. 생성된 패키지 파일 9개 모두 Git 제외 규칙을 확인했다.

## 필수 구성 축소 작업의 사전 실패 시나리오

- 묶음 압축을 위해 전부 메모리에 펼침: 조회한 묶음만 해제하고 기존 블록 상한을 유지한다. Python에서 만든 합성 v2 패키지를 Dart에서 복원하는 호환성 시험을 수행한다.
- 완료 전에 불완전한 구성 배포: 총량 제한·구성 파일 해시·전체 복원 검증 후에만 최종 구성 manifest를 만든다. PC 원본과 기존 패키지는 덮어쓰지 않는다.

## 구현 전 실패 시나리오

- 압축·중복 제거로 수치, 부정문, 조건 또는 약물 관계가 바뀜: 모든 약물 레코드를 복원해 입력 원문과 비교한다. 조회 없음은 안전으로 해석하지 않는다.
- 원문 문서를 AI 요약으로 대체하거나 도표를 잃음: 본문을 추출하고 원래 PDF의 페이지 보기를 함께 보존한다. 변환은 임상 검수를 대신하지 않는다.
- 오래된 답변의 근거가 새 문서로 바뀜: 패키지 해시·출처·위치·본문 해시로 고정한 인용만 연다.
- 잘린 패키지, 변조 DB, 압축 폭탄, 경로 탈출: 크기 상한과 해시를 검사하고, 오프라인 읽기 전용 접근 및 허용된 스키마만 사용한다.
- 미검수 자료가 앱의 의료 답변에 사용됨: 개발용 패키지와 미리보기만 지원하고 의료 생성용 접근을 차단한다. 자동 승인 옵션은 제공하지 않는다.
- 전체 자료를 메모리에 올리거나 원문을 두 번 저장함: 콘텐츠를 중복 제거한 압축 블록으로 저장하고 조회한 레코드·페이지에 필요한 블록만 해제한다.
- 변환 실패가 이전 결과를 덮어씀: 새 출력 경로에서 만든 뒤 완료 manifest를 마지막에 작성하고 이전 스냅샷은 보존한다.

실기기 실행 검증은 사용자의 기존 요청대로 배포 준비 직전으로 둔다. 이번 작업은 PC 변환 검증, Flutter 단위·위젯 시험과 개발용 오프라인 열람까지 수행한다.

## 구현과 사용

`care-knowledge-preview-v1`은 SQLite 안에 콘텐츠 해시로 중복 제거한 zlib 블록을 저장한다. 원본 JSON 필드, 빈 문자열·null, 제품별 변형, DUR 병용 방향과 조건을 보존한다. 모든 약물 레코드는 작성 직후 저장된 블록에서 복원해 입력과 대조한다. 검색·조회 인덱스는 압축을 풀지 않고 접근하며 본문은 해당 레코드나 페이지를 읽을 때만 해제한다. HTML/스크립트를 실행하거나 API·원문 URL에 접속하지 않는다.

Python 변환기와 Dart 읽기 전용 구현은 동일한 형식을 사용한다. DB 해시 검사·조회·압축 해제는 UI isolate 밖에서 처리한다. 블록과 복원 문자열은 16MiB 상한을 적용하며, 파일 크기·해시·DB 스키마·내부 메타데이터·블록 무결성을 검사한다. 해시는 손상과 버전 혼동을 탐지하는 값이며 **발행자 서명이나 임상 승인을 대신하지 않는다**. 이후 추가한 앱 고정 허용 목록과 설치기는 앞의 설치·검색·챗봇 연결 절을 따른다. 원격 서명 배포는 구현 범위에 포함하지 않는다.

`KnowledgeCitation`은 패키지 SHA-256, 출처 ID, 물리적 페이지 번호, 본문 SHA-256, 인용문 및 UTF-16 시작 위치를 고정한다. 일치하지 않는 버전·구절은 표시하지 않는다. 인용 카드, 문맥을 포함한 본문, 출처 정보, 원문 링크, 앞뒤 페이지, 확대 가능한 페이지 이미지를 오프라인에서 열람한다. 발행일과 검수일이 미확인인 자료에는 임의의 날짜를 넣지 않는다.

PDF는 pypdf로 텍스트를 추출하고 Poppler로 144DPI 페이지 이미지를 렌더링한다. WebP 인코딩은 무손실이며, 렌더링 이미지와 디코딩 이미지의 모든 픽셀을 대조한다. **PDF 파일 자체의 무손실 압축은 아니다.** 벡터·미세 글씨·외부 동영상은 원본 PDF 수준으로 보존되지 않으며 텍스트 읽기 순서·표의 의미는 추가 검수가 필요하다. 원본 PDF는 PC에 그대로 보존한다. HTML은 저장된 main 본문과 로컬 그림을 추출하며 외부/누락 그림이나 경로 이탈은 실패 처리한다.

원래 FTS5 읽기 API는 원문 언어의 기본 키워드 검색이다. 추가한 `KnowledgeSearch`가 한국어/영어 검색어 확장과 제목 검색을 수행하지만 임상 검색 KPI나 의미 검색 성능을 확보했다는 뜻은 아니다. 앱의 개발용 검색 화면과 별도 미리보기 진입점에서 열람할 수 있다. 미검수 자료는 `runtime_rag_eligible=false`, `mobile_bundle=false`, `do_not_train=true`를 유지하고 의료 답변 경로에는 전달하지 않는다.

## 재현 명령

### 2026-09-23 약물 연결과 배포 전 평가

약 목록의 **약물 주의자료 확인**에서 실제 포장과 제품명·업체·품목코드를 비교해 사용자가 연결한다. 이름 검색은 제품 후보이며 안전 판정이나 성분 동등성 판정이 아니다. SQLCipher 스키마 v6의 `medication_product`는 수첩·약 버전·자료 release에 묶인다. 약 변경/보관 시 연결을 삭제하며, 자료 변경/백업 복원 시 재확인이 필요하다. 선택 백업 문서 v5는 약과 처방 이력을 보존하지만 이 기기의 확인 권한은 옮기지 않는다.

`MedicationSafetyService`와 `DrugSafetyRules`는 LLM 없이 정확한 품목코드를 대조한다. 두 품목이 모두 선택된 병용 관계, 동일 제품의 중복 등록, 개별 DUR 주의 원문을 표시한다. 효능군·나이·임신·용량·기간은 개별 적용을 추정하지 않고 조건·예외를 포함한 원문 확인에 한정한다. 정규화된 성분/효능군 임상 규칙이 없는 상태에서 성분명 문자열만으로 중복 복용을 단정하지 않는다. 제품당 1,000행, 전체 3,000행의 보수적 상한을 넘으면 불완전 조회로 보류한다. 미검수·만료·손상·미확정·지원하지 않는 유형·늦게 완료된 다른 세션의 결과도 보류한다. 현재 배포 허용 목록은 계속 비어 있으므로 실제 자료의 의료 주의 결과는 아직 활성화되지 않는다.

설치 취소는 기존 활성 자료를 유지하며, 로딩/오류를 자료 없음과 구분한다. 파일 해시는 작업 isolate에서 계산한다. 사용성 시험에는 작은 화면과 큰 글자, 자료 없음, 설치 취소를 포함한다.

개발 평가 산출물은 `experiments/mobile_release_v1/`에 분리했다. 한국어 개발 질의의 상위 3개 문서 주제 적중은 5/10에서 표현 확장 후 10/10이며, 이 질의들은 개선에 사용했으므로 독립 평가나 임상 검색 정확도가 아니다. 욕창/인슐린 용량 범위 밖 2질의는 결과 없음이다. 현재 GGUF의 근거 선택 프롬프트는 생각 출력 종료 접미사를 추가해 제한된 토큰을 JSON에 쓰도록 수정했다. CPU 2스레드의 합성 시험은 5/6이고, 근거에 없는 가격 질문에 ID를 선택한 실패가 남는다. 검수된 동등 질문 목록에 없는 질문은 호스트가 모델 전에 막는다.

한국어 ONNX 인식기만의 합성 줄 이미지 100건은 100/100 문자 일치(5종 변형)다. 실제 카메라·문서 검출·손글씨 정확도로 해석하지 않는다. 2026-09-11에 저장된 네이티브 출력 재채점은 OCR 19/20, 음성 1/4 완전 일치이고 음성 숫자·단위 불일치 1건이다. 새 실기기 실행을 한 것이 아니며 OCR/음성의 사용자 확인 전 저장 금지를 유지한다.

자료 감사는 문서 13종 30페이지 및 약물 출처 11개에 대해 저장 원본 해시/본문 해시/빈 본문/대체 문자/메타데이터를 확인한다. 문서 13종 원본 해시는 모두 일치하지만 발행·개정일, 이미지 권리, 대상 환자, 추출 순서, 임상 검수는 미완료다. 수집일을 발행일이나 검수일로 대체하지 않는다.

이용조건의 2026-09-23 기술 검토(법적/임상 승인이 아님): [NHS 약관](https://www.nhs.uk/our-policies/terms-and-conditions/) 3.6–3.7에 따라 번역·문맥 변경 및 일정 기간 갱신하지 않은 콘텐츠의 표시 조건을 결정해야 한다. [CDC](https://www.cdc.gov/other/agencymaterials.html)는 출처·비보증·무료 원본 안내 및 외부 이미지 권리를 확인해야 한다. [NIDCR](https://www.nidcr.nih.gov/about-us/web-policies), [NIA](https://www.nia.nih.gov/about/policies), [AHRQ](https://www.ahrq.gov/policy/electronic/disclaimers/index.html)도 각 파일/그림의 조건을 별도 검토한다. [DUR](https://www.data.go.kr/data/15059486/openapi.do) 및 [허가정보](https://www.data.go.kr/data/15095677/openapi.do) 포털의 이용허락과 앱 내부 임상 검수는 별개다. 자동 감사로 승인 상태를 변경하지 않는다.

배포 직전에는 Android/iOS 실기기, 장기간 메모리·배터리, 권한·백업·업데이트, 정식 서명, 스토어 개인정보/건강 앱 선언을 확인한다. iOS는 Mac/Xcode와 네이티브 AI 연결 검증이 필요하며 현재 미검증이다.

프로젝트 루트에서 실행한다. 문서 변환에만 `scripts/requirements-knowledge.txt`와 Poppler가 필요하며 의약품 변환은 Python 표준 라이브러리를 사용한다. 출력 폴더는 **존재하지 않는 새 경로**여야 한다.

```powershell
python scripts/build_drug_knowledge_pack.py --snapshot data/mfds/permits/20260918T053000Z --output data/knowledge-preview/permits-v1
python scripts/build_drug_knowledge_pack.py --snapshot data/mfds/dur/20260918T053000Z --output data/knowledge-preview/dur-v1
python scripts/build_easy_drug_knowledge_pack.py --snapshot data/easy-drug/raw/20260901T061358Z --output data/knowledge-preview/easy-drug-v1
python scripts/build_document_knowledge_pack.py --output data/knowledge-preview/documents-v1 --pdftoppm <pdftoppm.exe 경로>
```

`mobile`에서 개발용 진입점을 실행한다. 지정 경로는 **실행 기기에서 접근 가능한 폴더**이며 `manifest.json`과 `knowledge.sqlite3`가 함께 있어야 한다. PC의 `E:` 경로가 휴대전화에서 그대로 동작하지 않는다. 공개 앱의 설정에는 이 도구를 노출하지 않고 release 모드 실행도 차단한다.

```powershell
flutter run -t tool/knowledge_preview.dart --dart-define=CARE_KNOWLEDGE_PREVIEW_PATH=<실행 기기의 패키지 폴더>
dart run tool/knowledge_pack_probe.dart ../data/knowledge-preview/permits-v1 ../data/knowledge-preview/dur-v1 ../data/knowledge-preview/easy-drug-v1 ../data/knowledge-preview/documents-v1
flutter test --no-pub test/knowledge_package_test.dart test/knowledge_document_ui_test.dart test/ai_evidence_ui_test.dart
```

합성 Python↔Dart 호환성 fixture는 루트에서 `python -m scripts.build_knowledge_test_fixture`로 재생성한다. 실제 자료, 생성 DB와 이미지 QA 파일은 기존 `/data/*` ignore 규칙에 따라 Git에 포함하지 않는다. 인증키와 `.env`는 읽거나 패키지에 넣지 않는다.

## 이전 v1 보존용 패키지의 변환 결과

아래 용량은 MiB(1,048,576바이트)이며 각 패키지 DB 기준이다. 원본 API 응답과 기존 PC용 인덱스를 함께 합산한 수치를 비교 기준으로 부풀리지 않았다.

| 자료 | 기존 비교 대상 | 경량 패키지 | 내용 보존 검사 |
|---|---:|---:|---|
